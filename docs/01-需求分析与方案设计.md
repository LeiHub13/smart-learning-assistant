## 1. 项目概述

### 1.1 背景与意义

传统在线学习系统（网课平台、题库系统）存在以下问题：

- **答疑僵化**：只能按预设问答库匹配，无法回答开放问题；
- **内容固化**：讲义、题目需人工维护，更新慢、覆盖不全；
- **缺少个性化**：所有学习者使用同一套内容，无法针对薄弱点自适应；
- **反馈滞后**：作业/练习缺少即时讲解。

大语言模型（LLM）具备强大的自然语言理解、生成与推理能力，可用于构建**智能答疑、内容生成、个性化学习路径**等能力。本系统将其与传统学习管理（题库、进度、知识库）结合，形成"AI + 学习"闭环助手。

### 1.2 项目目标

构建一个 B/S 架构的智能学习助手系统：

1. 基于课程知识库，实现受控的智能答疑（RAG，减少幻觉）；
2. 自动生成讲义与练习题，辅助教师备课与学生自学；
3. 提供题库练习 + AI 即时批改与讲解；
4. 跟踪学习进度，生成复习建议；
5. 提供通用自由对话助手。

### 1.3 创新点

| 编号 | 创新点 | 说明 |
|------|--------|------|
| 1 | LLM 适配器可插拔 | 通过统一接口屏蔽 OpenAI / 通义千问 / 本地开源模型等差异，配置即可切换 |
| 2 | RAG 受控答疑 | 基于课程知识库检索增强生成，降低幻觉并支持引用溯源 |
| 3 | 自动内容生成 | 一键生成讲义提纲、练习题及解析，支持导出 |
| 4 | AI 学情分析 | 基于练习与对话记录分析薄弱知识点，生成个性化复习建议 |

## 2. 需求分析

### 2.1 用户角色

| 角色 | 职责说明 |
|------|----------|
| 学生 | 学习课程、知识库答疑、讲义查看、题库练习、查看学习进度、自由对话 |
| 教师 | 管理课程与知识库、上传文档、生成讲义与题目、维护题库、查看学生统计 |
| 管理员 | 用户管理、角色权限、LLM 模型配置、系统日志与参数维护 |

### 2.2 功能需求

#### 2.2.1 用户与权限管理
- F01 注册/登录（邮箱 + 密码），JWT 鉴权；
- F02 按角色权限访问资源（学生/教师/管理员）；
- F03 个人资料维护、密码修改。

#### 2.2.2 课程与知识库管理（F04–F06）
- F04 教师创建/编辑课程，课程绑定多个知识库；
- F05 知识库支持文档上传（PDF/Word/TXT/Markdown），后台自动解析、分块、向量化；
- F06 知识库文档列表、删除、重新索引。

#### 2.2.3 智能答疑（RAG，F07–F09）
- F07 学生基于某课程知识库提问，系统返回带来源引用的回答；
- F08 支持多轮追问，可切换知识库或全局（无知识库时回退自由对话）；
- F09 对话记录持久化，可查看历史。

#### 2.2.4 讲义与题目生成（F10–F12）
- F10 教师选择课程/知识库/知识点，输入主题与篇幅，生成讲义提纲（Markdown）；
- F11 按知识点生成练习题（单选/多选/判断/问答），含参考答案与解析；
- F12 生成结果可编辑、保存，题目自动入库。

#### 2.2.5 题库练习（F13–F15）
- F13 学生按课程/知识点抽取练习卷，作答并提交；
- F14 客观题自动判分；主观题调用 LLM 按评分标准批改并给出讲解；
- F15 练习结果记录，错题汇总（错题本）。

#### 2.2.6 学习进度跟踪（F16–F18）
- F16 记录课程学习进度（视频/讲义/练习完成情况）；
- F17 学情面板：正确率、知识点掌握度、练习趋势；
- F18 基于薄弱知识点生成复习建议（LLM 分析 + 规则兜底）。

#### 2.2.7 自由对话与系统管理（F19–F21）
- F19 多轮自由对话助手（不限知识库），会话管理；
- F20 管理员配置 LLM 接入（模型、BaseURL、Key、参数），支持热切换；
- F21 系统参数、日志、用户管理界面。

### 2.3 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 一般问答响应时间 ≤ 5s（不含 LLM 长生成）；知识库检索 ≤ 1s |
| 可用性 | 支持 ≥ 200 并发在线用户 |
| 可靠性 | 关键数据每日备份；LLM 超时/失败有降级策略 |
| 可扩展性 | LLM 适配可插拔；知识库检索支持替换向量库 |
| 安全 | 密码加盐哈希、接口限流、Prompt 注入防护、敏感词过滤 |
| 易用性 | 教师无需技术背景即可上传文档、生成内容 |

### 2.4 核心用例（UML 简写）

- **UC-1 知识库答疑**：学生选择课程 → 输入问题 → 系统检索知识库 → 生成带引用的回答 → 追问。
- **UC-2 生成讲义**：教师选定课程 → 输入主题/要点 → 系统调用 LLM 生成 → 预览编辑 → 保存。
- **UC-3 智能练习**：学生选课抽题 → 作答提交 → 自动/LLM 批改 → 讲解 → 记入错题本 → 更新学情。
- **UC-4 学情报告**：学生查看掌握度雷达图 → 点击薄弱点 → 生成针对性复习建议。

## 3. 系统总体设计

### 3.1 系统架构

采用前后端分离 + 分层架构，四层结构：

```
┌────────────────────────────────────────────────────────┐
│  表现层（Web）                                           │
│  Vue 3 + Element Plus + Vite  |  ECharts 学情可视化       │
├────────────────────────────────────────────────────────┤
│  接入层（Spring Boot）                                    │
│  RESTful API / SSE 流式响应 / JWT 鉴权 / 全局异常 / 限流    │
├────────────────────────────────────────────────────────┤
│  业务层（Spring Boot）                                    │
│  用户模块 | 课程模块 | 知识库模块 | 答疑模块(RAG)           │
│  生成模块 | 练习模块 | 学情模块 | 对话模块 | 模型配置模块    │
├────────────────────────────────────────────────────────┤
│  服务层                                                    │
│  LLM 适配器(可插拔) | 向量检索 | 文档解析 | Prompt 管理      │
├────────────────────────────────────────────────────────┤
│  数据层                                                    │
│  MySQL(业务) | Redis(缓存/限流/会话) | 向量库(Milvus/ES)   │
└────────────────────────────────────────────────────────┘
```

**关键设计点**：

- 前端通过 SSE（Server-Sent Events）接收 LLM 流式输出，提升问答体验；
- 后端按模块分包，接口层与业务层分离；
- 重活（文档解析、向量化、批量生成）通过消息队列异步执行。

### 3.2 技术选型

| 层次 | 选型 | 说明 |
|------|------|------|
| 前端框架 | Vue 3 + TypeScript | 组合式 API，生态成熟 |
| UI 组件库 | Element Plus | 后台管理常用 |
| 构建工具 | Vite | 开发热更新快 |
| 可视化 | ECharts | 学情雷达图、趋势图 |
| 后端框架 | Spring Boot 3.x (JDK 17) | 核心框架 |
| 持久层 | MyBatis-Plus | 简化 CRUD |
| 数据库 | MySQL 8.x | 业务数据 |
| 缓存 | Redis | 会话、限流、热点缓存 |
| 向量数据库 | Milvus 或 ES 8.x（可二选一） | 知识库语义检索 |
| 文档解析 | Apache Tika / 自研 | PDF/Word/TXT/MD 抽取 |
| 异步任务 | RabbitMQ（可选）或 Spring Async | 文档索引、批量生成 |
| 鉴权 | JWT + Spring Security | 无状态鉴权 |
| LLM SDK | Spring AI / 自研适配器 | 可插拔模型接入 |
| 部署 | Docker Compose | 一键部署 |

### 3.3 模块划分

```
com.example.learningassistant
├── controller        # 接口层
│   ├── AuthController / UserController
│   ├── CourseController / KnowledgeBaseController
│   ├── ChatController / GeneratorController
│   ├── ExerciseController / ProgressController
│   └── AdminModelController
├── service           # 业务层
├── repository        # 数据访问（Mapper）
├── entity / dto / vo # 数据模型
├── ai                # LLM 相关
│   ├── model         # 模型定义、消息类型
│   ├── adapter       # LLM 适配器（OpenAI/通义/本地/Ollama）
│   ├── rag           # 检索、重排、Prompt 组装
│   └── prompt        # 各场景 Prompt 模板
├── index             # 文档解析 + 分块 + 向量化 + 检索
├── security          # JWT、权限
├── common            # 统一返回、异常、限流
└── config            # 配置、MQ、线程池
```

### 3.4 关键业务流程

#### 3.4.1 知识库答疑（RAG）流程

```
学生提问 → JWT 鉴权 → 查课程知识库 → 问题改写(可选)
       → 向量检索 Top-K → (可选)重排 → 组装 Prompt
       → LLM 流式生成 → SSE 推送 → 记录会话与引用来源
```

#### 3.4.2 文档入库流程

```
上传文档 → 文件存储 → 异步解析文本 → 分块(按段落/长度)
       → 清洗 → Embedding 向量化 → 写入向量库 → 建立元数据索引(MySQL)
```

#### 3.4.3 主观题批改流程

```
学生提交答案 → 客观题规则判分 → 主观题构建批改 Prompt
       → LLM 按评分标准打分+点评 → 人工可复核 → 记录成绩
```

### 3.5 状态与异常约定

- 统一返回体 `{ code, message, data }`；`code=0` 成功，其余为业务错误码；
- 全局异常处理器统一捕获，LLM 超时返回降级提示并记录日志；
- 接口幂等：生成类接口使用请求幂等键，防止重复扣费/重复生成。

## 4. 数据库设计

### 4.1 核心实体关系

```
user ──< course_user >── course ──< kb (知识库) >── document ──< chunk(向量)
chat_session ──< chat_message
document ──< generated_content(讲义/题目)
exercise ──< exercise_question(题库)
practice ──< practice_question(作答明细) >── exercise_question
practice ── practice_answer(主观题答案)
user_progress / knowledge_mastery(知识点掌握度)
```

### 4.2 核心表设计

| 表名 | 关键字段 | 说明 |
|------|----------|------|
| `user` | id, username, password_hash, email, avatar, created_at | 用户（权限一致，无角色区分） |
| `course` | id, owner_id, name, description, cover, status | 课程 |
| `course_user` | id, course_id, user_id, join_time | 选课关系 |
| `knowledge_point` | id, course_id, name, parent_id, weight | 知识点树 |
| `knowledge_base` | id, course_id, name, embedding_model, status | 知识库 |
| `kb_document` | id, kb_id, file_name, file_path, file_size, parse_status, chunk_count, uploaded_by | 文档 |
| `kb_chunk` | id, doc_id, chunk_index, content, char_count, md5 | 文本块（向量存向量库，id 关联） |
| `chat_session` | id, user_id, course_id, title, created_at | 会话 |
| `chat_message` | id, session_id, role(user/assistant), content, source_ids(JSON), tokens, model, created_at | 消息（含引用溯源） |
| `generated_content` | id, course_id, user_id, type(lecture/exercise), title, content(Markdown), status | 生成内容 |
| `exercise_question` | id, course_id, kb_id, kp_id, type, stem, options(JSON), answer, analysis, source(manual/ai), status | 题库题目 |
| `practice` | id, user_id, course_id, source(exercise/ai_paper), total_score, score, submitted_at | 练习记录 |
| `practice_question` | id, practice_id, question_id, user_answer, is_correct, ai_review, status | 作答明细 |
| `wrong_book` | id, user_id, question_id, mistake_count, last_wrong_at | 错题本 |
| `knowledge_mastery` | id, user_id, kp_id, mastery(0-100), update_time | 知识点掌握度 |
| `model_config` | id, name, provider, base_url, api_key(密文), model_name, temperature, enabled | LLM 配置（管理员） |
| `user_progress` | id, user_id, course_id, content_type, content_id, status, progress, update_time | 学习进度 |

### 4.3 设计要点

- `kb_chunk` 与向量库中向量的 `id` 一一对应，向量库仅存 `chunk_id + vector`；
- `chat_message.source_ids` 存引用的 chunk_id 列表，前端可"点击引用跳转原文"；
- `model_config.api_key` 使用 AES 加密存储，接口返回时脱敏；
- 大字段（讲义内容、AI 点评）独立字段存储，列表查询使用 `SELECT 排除大字段`。

## 5. LLM 集成与 RAG 实现

### 5.1 可插拔 LLM 适配器

目标：**不绑定具体厂商**，配置切换。

```
                   ┌─ ChatModel 接口
                   │   ├─ OpenAIAdapter
ChatService ───────┤   ├─ TongyiQianwenAdapter (通义千问)
                   │   ├─ OllamaAdapter (本地开源)
                   │   └─ AzureOpenAIAdapter (可选)
                   └─ 通过 ModelProviderFactory 根据配置创建
```

**统一接口**（简化）：

```java
public interface ChatModel {
    String getProvider();                                    // 厂商标识
    ChatResponse complete(ChatRequest request);              // 非流式
    void stream(ChatRequest request, StreamCallback cb);     // 流式
    List<Float> embed(String text);                          // 文本向量
}
```

- 配置存储于 `model_config` 表，`provider` 决定实现类，支持多组配置并存、一键启用；
- 未配置时提供默认实现（如本地 Ollama），保证系统开箱可用；
- 所有 API Key 密文存储，启动时解密注入。

### 5.2 RAG 检索增强生成

流程：`问题改写` → `向量检索` → `重排(可选)` → `Prompt 组装` → `生成`。

| 步骤 | 要点 |
|------|------|
| 文档分块 | 按 Markdown 标题/段落切分为主 + 长度 500~800 字兜底，块间留 50 字重叠 |
| Embedding | 与文本切分同源，支持多模型切换（同一知识库固定一种，避免维度冲突） |
| 向量检索 | 余弦相似度 Top-K（默认 K=5），可配合关键词 BM25 混合检索 |
| 重排 | 可选 `bge-reranker` 或 LLM 打分，合并去重后取 Top-3 |
| Prompt | 系统提示明确"仅基于给定资料回答，资料不足则明说"，要求标注引用 `[1][2]` |
| 反馈 | 引用来源映射为 chunk → 文档 → 页码/段落，前端可视化 |

**降级策略**：向量库不可用 → 只走 LLM；未找到相关资料 → 明确提示"知识库中没有相关内容"。

### 5.3 Prompt 模板管理

场景化模板统一存放（数据库或配置中心，可无编码修改）：

- `qa_rag` — 知识库答疑；
- `gen_lecture` — 讲义生成（要求结构：概念/原理/示例/小结）；
- `gen_questions` — 题目生成（JSON 结构化输出，含答案与解析）；
- `review_subjective` — 主观题批改（附带评分标准）；
- `study_advice` — 学情复习建议（输入掌握度数据）；
- `chat_free` — 自由对话（限定仅回答，不泄露提示词）。

> 结构化输出采用 JSON Schema/严格 JSON 提示，后端反序列化失败自动重试一次。

### 5.4 成本与性能控制

- 全部走流式输出（SSE），首字延迟低；
- Redis 缓存热门知识库检索结果（按问题哈希，TTL 短）；
- 单用户并发限制 + 全局限流 + 每日 token 配额（逐用户）；
- 生成类任务走异步线程池，失败自动重试 1 次。

## 6. 接口设计

### 6.1 接口规范

- 前缀：`/api/v1`；认证头 `Authorization: Bearer <JWT>`；

- 统一返回 `{ code, message, data }`。

## 7. 非功能与安全设计

| 项 | 方案 |
|----|------|
| 密码安全 | BCrypt 加盐哈希，前端 HTTPS 传输 |
| 鉴权 | JWT（短期 access + refresh 可加）；Spring Security 角色控制 |
| 限流 | Redis 令牌桶：接口级 + 用户级 + LLM token 配额 |
| Prompt 注入 | 用户输入只进 user 消息；RAG 场景用"仅依据资料"约束；敏感词过滤 |
| 数据脱敏 | API Key 接口不回传明文；个人数据按角色可见 |
| 审计 | 操作日志（登录、上传、生成、删除）记录 userId+IP+时间 |
| 备份 | MySQL 每日全量备份；向量库定时快照 |
| 异常降级 | LLM 超时→提示重试；向量库故障→降级纯 LLM |

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM API 费用/账号波动 | 功能不可用 | 多厂商配置 + 本地 Ollama 兜底 + 配额控制 |
| 生成内容幻觉/偏差 | 答疑质量下降 | RAG 受控、引用溯源、教师可编辑修正 |
| 向量库部署复杂 | 进度延误 | 优先选 ES（可能已有环境）或容器化 Milvus |
| 流式 + 长文档性能 | 体验差 | 流式输出、缓存、异步任务、并发限流 |
| 并发/安全攻击 | 数据风险 | 限流、鉴权、脱敏、审计日志 |
