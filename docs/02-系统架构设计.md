## 1. 设计目标与原则

### 1.1 设计目标

| 目标 | 说明 |
|------|------|
| 演示稳定 | 双进程一键启动（Java + Python），H2 免安装，内存降级实现开箱即用 |
| AI 能力平台化 | AI 与业务解耦：业务只面向 `ChatModel` 接口编程，底层可 Python 服务 / 直连厂商 |
| 流式体验 | 对话、生成全链路 SSE 逐字透传（Java → Python → 前端），非全文返回后模拟 |
| 可演进 | Java 骨架预留中间件切换点（缓存/向量/存储/MQ），AI 服务预留多厂商路由 |

### 1.2 设计原则

1. **业务与 AI 分离**：Java 负责业务与数据（检索、落库、判分、聚合），Python 负责大模型能力（生成、批改、记忆）。Java 只关心 `ChatModel` 接口（`complete` / `stream`），不关心底层实现。
2. **协议简单**：Java ↔ Python 采用单一 JSON 协议 + 场景标记映射，六种业务场景共用一个接口。
3. **记忆归属单一**：会话记忆由 Python 端按 `sessionId` 管理（JSONL 持久化），Java 不重复存上下文。
4. **中间件按需降级**：缓存/向量/存储/MQ 均有内存降级实现，未配置中间件即开箱可用。
5. **安全内建于框架**：JWT 双 Token + 拦截器统一鉴权；LLM Key 只存在于 ai-service/.env，不进入 Java 与前端。

## 2. 总体架构

### 2.1 架构分层图

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 表现层：Vue3 单页应用（Vite dev server，/api 代理到后端）                     │
│  Login / Chat(SSE流式答疑) / Generate(讲义·出题) / Practice(练习·批改)        │
│  Progress(学情·AI建议) / Manage(课程·知识库·文档管理)                          │
└───────────────────────────────┬────────────────────────────────────────────┘
                                │ HTTP/1.1 + SSE（fetch + ReadableStream 逐字渲染）
┌───────────────────────────────▼────────────────────────────────────────────┐
│ Java 业务骨架（Spring Boot 3，单模块，端口 8080）                             │
│  web/controller（Auth/Course/Kb/Chat/Generate/Practice/Progress/Analytics）│
│  业务领域：user / course / kb(RAG检索) / chat / generate / practice          │
│            / progress / exam / assignment / analytics / recommend / notify  │
│  ai/：ChatModel 接口（python-langchain | openai-compatible 适配器）      │
│  infra/：cache / vector / storage / mq 四类基础设施（内存降级 + 真实实现）      │
└───────────────────────────────┬────────────────────────────────────────────┘
                                │ HTTP /ai/complete（非流式）
                                │ HTTP /ai/stream（SSE 流式）
┌───────────────────────────────▼────────────────────────────────────────────┐
│ Python AI 服务（FastAPI + langchain，端口 8000）                             │
│  /ai/health（健康检查） /ai/complete /ai/stream /ai/history/{sessionId}      │
│  chains.py：6 场景链（rag_qa/free/lecture/questions/review/advice）          │
│  memory.py：会话记忆（JSONL，按 sessionId，最近 5 轮）                        │
│  config.py：读取 .env（提供商/Key/模型/BaseURL）                              │
└───────────────────────────────┬────────────────────────────────────────────┘
                                │ OpenAI 兼容协议 /chat/completions
┌───────────────────────────────▼────────────────────────────────────────────┐
│ 在线大模型：DeepSeek / 通义千问 / OpenAI 等（ChatOpenAI 适配）                 │
└────────────────────────────────────────────────────────────────────────────┘

数据层：H2 文件库（MODE=MySQL，可平滑切 MySQL）/ 文件存储本地目录（可切 MinIO）
```

### 2.2 关键设计点

- **双进程职责边界**：
  - Java：鉴权、会话与消息落库、RAG 向量检索（t_chunk + 内存向量库）、练习判分与掌握度聚合、生成内容入库。
  - Python：大模型调用（流式/非流式）、场景 Prompt 编排、会话记忆管理。
- **场景标记协议**：Java 在 system 消息首行写场景标记（`RAG_QA`/`FREE`/`GEN_LECTURE`/`GEN_QUESTIONS`/`REVIEW_SUBJECTIVE`/`ADVICE`），`PythonAIChatModel` 解析为 Python 场景（`rag_qa`/`free`/`lecture`/`questions`/`review`/`advice`）；`【知识库资料】…【资料结束】` 包裹的块解析为 `chunks` 数组；`SESSION_ID:xxx` 行指定会话记忆标识。Java 侧源码不动即完成模型切换。
- **SSE 双跳透传**：Java `ChatController` 以 `SseEmitter` 对外；`PythonAIChatModel` 用独立 daemon 线程读 Python 的 SSE 流并逐块回调 `onDelta`，两端事件格式一致（`{"delta":"字"}` / `{"done":true}` / `{"error":"..."}`），首字延迟 = Python 服务首字延迟。
- **引用溯源**：RAG 检索在 Java 完成（Top-N 块带 `[n]` 编号），Python 只做生成；回答中的 `[n]` 引用由 Java 回填为知识库片段编号回显前端。
- **启动自愈**：后端启动时 `DataSeeder` 幂等建演示数据 + `KbService.reindexFromChunks()` 用 t_chunk 表重建内存向量库，重启不丢检索能力。

## 6. Java ↔ Python AI 服务协议

### 6.1 健康检查

```
GET http://localhost:8000/ai/health
→ {"status":"ok","provider":"deepseek","model":"deepseek-chat","baseUrl":"https://api.deepseek.com"}
```

### 6.2 非流式生成

```
POST /ai/complete
{ "scene": "lecture", "question": "...", "chunks": ["..."], "sessionId": "..." }
→ { "content": "..." }
```

### 6.3 流式生成（SSE）

```
POST /ai/stream   （body 同 /ai/complete）
→ event: message
  data: {"delta":"字"}
  ...
  data: {"done":true}
  错误时：data: {"error":"..."}
```

### 6.4 场景与标记映射

| Java 场景标记（system 首行） | Python scene | 用途 | 输出 |
|-------------------------------|--------------|------|------|
| RAG_QA | rag_qa | 知识库答疑（带 [n] 引用） | Markdown |
| FREE | free | 自由对话 | 文本 |
| GEN_LECTURE | lecture | 讲义生成 | Markdown |
| GEN_QUESTIONS | questions | 题目生成 | JSON 数组（type/stem/options/answer/analysis/kpName） |
| REVIEW_SUBJECTIVE | review | 主观题批改 | JSON（{"score":0-10,"comment"}） |
| ADVICE | advice | 学情复习建议 | 分条文本 |

- `【知识库资料】…【资料结束】` 之间的内容按行解析为 `chunks` 数组（Java 侧剥除 `[n]` 前缀，由 Python 统一编号，编号顺序 = 检索相关度顺序）；
- `SESSION_ID:xxx` 行 → `sessionId` 字段（仅 rag_qa/free 参与记忆）。

## 7. 核心链路设计

### 7.1 RAG 答疑链路（SSE 双跳）

```
前端 ChatView ── POST /api/chat/sessions/{id}/stream ──> ChatController(SseEmitter)
  → ChatService:
     ① 校验会话/知识库归属，保存用户消息
     ② KbService 向量检索：查询文本 → 哈希 n-gram 嵌入 → 余弦相似度 Top-N
        → 组装 "[n] 内容" 上下文；无命中则携带"暂无相关资料"
     ③ system = 场景标记 + 知识库资料 + SESSION_ID
     ④ ChatModelFactory.get().stream(messages, onDelta, onDone, onError)
        └─ PythonAIChatModel：POST /ai/stream（独立线程读 SSE）→ onDelta 透传
     ⑤ 完成后保存 assistant 消息（含 sources 引用编号）→ 记 t_llm_call_log
  → SseEmitter 逐块 send({"delta":...}) → 前端 ReadableStream 逐字渲染 + 引用角标
```

### 7.2 题目生成入库链路

```
GenerateView ── POST /api/generate/questions ──> GeneratorService
  → ChatModel.complete(system=GEN_QUESTIONS, user=知识点+数量)
  → Python /ai/complete → JSON 数组 → Jackson 解析校验
  → 逐题写入 t_question（source=ai）→ 返回新题列表 → 前端展示答案/解析
```

### 7.3 练习判分与批改链路

```
PracticeView ── GET /api/practice/paper?courseId&count ──> 按知识点随机抽题（不带答案）
  ── POST /api/practice/submit {courseId, items:[{questionId, answer}]} ──> PracticeService
     客观题：规则判分（单选/判断忽略大小写；多选去除非字母后排序比较）
     问答题：ChatModel.complete(system=REVIEW_SUBJECTIVE) → Python review 场景
             → JSON {"score":0-10,"comment"} 落 t_practice_question
  → 汇总总分 + 更新 t_knowledge_mastery（attempts/correct_count → mastery 加权）
```

### 7.4 学情汇总与 AI 建议链路

```
ProgressView ── GET /api/progress/summary?courseId ──> ProgressService
  → masteries：t_knowledge_mastery 按知识点聚合
  → 错题与薄弱知识点 → system=ADVICE → Python advice 场景 → 分条复习建议
```

### 7.5 启动自愈链路

```
java -jar 启动 → schema.sql 建表（IF NOT EXISTS）
  → DataSeeder：无用户则建演示账号；无课程则建课程/选课/知识库/文档/分块/种子题目
  → KbService.reindexFromChunks()：t_chunk 全量读入内存向量库（重启不丢检索）
```

## 8. AI 场景与记忆设计

| 场景 | Prompt 要点 | 数据来源 |
|------|-------------|----------|
| rag_qa | 只依据【知识库资料】回答，标注 [n]；资料不足时明示"暂无相关资料" | Java 检索 Top-N chunk |
| free | 中文友好解答 | 会话记忆 |
| lecture | 输出 Markdown 讲义（# 标题、表格、示例） | 无（通用生成） |
| questions | 只输出 JSON 数组，字段 type/stem/options[{k,v}]/answer/analysis/kpName | 无 |
| review | 依据参考答案对 0-10 打分 + 点评，输出 JSON | 题目/参考答案/学生答案 |
| advice | 依据掌握度与错题给出复习建议，分条输出 | Java 传入掌握度统计 |

- **记忆策略**：`memory.py` 按 `sessionId` 读写 `data/memory/{sessionId}.jsonl`，拼入最近 5 轮（user/assistant 对），支持多轮指代（如"那它的负载因子默认是多少？"）；线程锁保证并发安全；Java 不重复携带历史。
- **失败策略（不降级）**：Python 服务不可用或调用失败时 Java 直接返回错误，不静默回退；AI 接入仅支持真实模型（python / openai-compatible），配置非法直接抛错。

## 9. 可降级基础设施

| 设施 | 接口 | 内存降级实现 | 真实实现（配置即切换） |
|------|------|--------------|------------------------|
| 缓存 | CacheService | InMemoryCacheService | RedisCacheService（cache-mode: redis） |
| 向量库 | VectorStore | InMemoryVectorStore（启动重建） | MilvusVectorStore（vector-mode: milvus） |
| 存储 | FileStorage | LocalFileStorage（./data/files） | MinioFileStorage（storage-mode: minio） |
| 消息 | MessagePublisher | InMemoryMessagePublisher | RabbitMessagePublisher（mq-mode: rabbit） |

配置见 `application.yml` 的 `app.infra.*`；`app.model.provider: python | openai-compatible` 切换 AI 接入方式，`app.model.python-base-url` 指向 ai-service。

## 10. 安全设计

| 维度 | 设计 |
|------|------|
| 认证 | JWT 双 Token：access(2h) + refresh(7d)；`AuthInterceptor` 拦截非白名单路径，`CurrentUser` 注入 |
| 授权 | 系统为个人学习助手，用户权限一致（无角色区分）；资源按 userId 隔离（会话/练习/掌握度仅本人可见） |
| 密钥管理 | LLM API Key 仅存 `ai-service/.env`（gitignore 外）；JWT 密钥在 application.yml 标注生产必改 |
| 参数安全 | 统一 ApiResponse + 全局异常处理，不泄露堆栈 |
| Prompt 安全 | 系统提示词强约束角色与输出格式；RAG 引用可溯源防幻觉 |
| 会话隔离 | 会话/练习数据按 userId 过滤，跨用户访问不可达 |

## 11. 部署架构

### 11.1 本地演示拓扑（当前）

```
前端 Vite :5173 ──/api 代理──> Java :8080 ──/ai/*──> Python :8000 ──> DeepSeek API
```

启动顺序：
```bash
# 1) Python AI 服务
cd ai-service && pip install -r requirements.txt && copy .env.example .env  # 填 AI_API_KEY
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 2) Java 骨架
cd backend && mvn package -DskipTests && java -jar target/learning-assistant-1.0.0.jar

# 3) 前端
cd frontend && npm install && npm run dev
```

### 11.2 生产预留

- Java 无状态多副本 + Nginx 负载均衡（SSE 需 `proxy_buffering off`）；
- ai-service 独立扩缩容（GPU/长连接密集），按场景路由不同模型；
- H2 换 MySQL（注释内置配置）、内存向量库换 Milvus、本地存储换 MinIO。

## 13. V2 规划与 V3 落地对照

| 维度 | V2 架构规划（模块化单体） | V3 落地（Java 骨架 + Python AI 服务） | 取舍理由 |
|------|--------------------------|---------------------------------------|----------|
| 工程形态 | 18 个 Maven 模块 | 单模块分包（业务域分包不变） | 毕设规模下模块化成本 > 收益；包边界保留演进余地 |
| AI 接入 | la-ai 模块（Java 适配器） | 独立 Python langchain 服务 | 大模型生态在 Python（langchain/向量库/Agent）；独立扩缩容 |
| 数据库 | MySQL 8 | H2（MODE=MySQL），配置即切 | 演示免安装；DDL 兼容 MySQL |
| 向量库 | Milvus/pgvector | 内存向量库 + t_chunk 重建 | 演示数据量级足够；接口不变可切 |
| 检索 | 向量 + BM25 混合 + 重排 | 向量相似度 Top-N（+ 无命中提示） | 数据量小，单路召回已满足演示 |
| LLM 流式 | WebClient 直连厂商 | Java→Python SSE 双跳透传 | 真流式体验等价，且 Python 侧更易扩展 Agent/工具 |
| 记忆 | Java 会话上下文 | Python JSONL 会话记忆 | 记忆与生成同侧，指代处理一致 |
| 鉴权 | Spring Security + RBAC | 自研 JWT 拦截器 + 角色校验 | 规模可控；标准库依赖最小化 |
| 可观测 | ELK + Prometheus + SkyWalking | 日志 + t_llm_call_log 审计 | 演示够用，指标系统按需引入 |
| 部署 | Docker Compose 全套中间件 | 双进程本地启动 | 演示环境零依赖 |

> 演进方向：V3 的结构是为"功能完整、演示稳定、答辩可讲清"服务的；V2 文档中的中间件与模块化方案作为演进路线保留（见 §12）。
