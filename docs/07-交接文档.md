## 三、关键集成点

1. **Agent 工具回调路径**
   - Python `app/agent.py` -> `JAVA_TOOL_BASE`（默认 `http://localhost:8080`）
   - Docker 环境需在 `docker-compose.yml` 中覆盖为 `http://backend:8080`
   - Java `InternalToolController` 检查 `X-Internal-Token` 头，与 `app.internal-tool-token` 配置对应

2. **新 Python 场景与 Java 标记映射**
   - `ChatService` system prompt 首行需增加对应场景标记：`REWRITE`、`RERANK`、`PLAN`、`REPORT`
   - `PythonAIChatModel` 需在 `toPayload` 中识别这些新标记

3. **数据库迁移**
   - 新安装：schema.sql 自动建表
   - 旧 H2/MySQL 实例：需要清空 `backend/data` 或手动删表重建，否则新增表不存在

## 六、已知风险

- `openpdf` 的 `STSong-Light` 字体在某些非 Adobe 阅读器里可能显示异常；如验收严格，可改用前端 `window.print()` 方案替代后端 PDF。
- Docker 内 Python Agent 调 Java 内部接口时，如网络/Token 配置错误会导致 Agent 返回「暂时无法获取该数据」，但不影响普通 RAG 答疑。
- 旧数据库实例因新增表，直接启动会报找不到表；Docker 新卷或删除旧 `backend/data` 可解决。
